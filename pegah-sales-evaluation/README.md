# pegah-sales-evaluation

اسکیل ارزیابی فروشنده پگاه، در فرمت استاندارد `SKILL.md`. مستقل است: این پوشه را
هرجا بگذاری کار می‌کند.

```
SKILL.md                      دستورالعمل — چیزی که مدل هر بار می‌خواند
rules.json                    آستانه‌ها، گام‌ها و ضریب‌ها (داده، نه کد)
scripts/score.py              نمره‌دهی
references/queries.md         کوئری‌های آماده و تست‌شده روی pakhsh
references/metrics.md         کدام جدول، کدام ستون، و کدام جدول‌ها مرده‌اند
references/reporting.md       شکل گزارش
examples/sample-input.json    نمونه ورودی کامل
```

## نگاشت داده

روی دیتابیس `pakhsh` (SQL Server) نوشته و تست شده:

| معیار | جدول |
|---|---|
| ۱ تعداد مغازه وزنی | `Sales.DarkhastFaktor` (`ccNoeMoshtary` ۳۴۷/۳۴۸/۳۵۰) |
| ۲ ویزیت مثبت | `Sales.VisitForoshandeh_Arshiv` |
| ۳ اقلام هر فاکتور | `Sales.VisitForoshandeh_Arshiv` |
| ۴ مشتری خرید کرده | `Sales.VisitForoshandeh_Arshiv` |
| ۵ مرجوعی | `Sales.ElamMarjoee` + `ElamMarjoeeSatr` |
| ۶ هدف گروه محصول | `Sales.HadafForoshandeh_PG` + `DarkhastFaktorSatr` |

دو تله که وقت زیادی می‌گیرند اگر از قبل ندانی:

- `Sales.AmalkardRozanehForosh` و `Sales.HadafForosh` دقیقاً به اسمِ همین کارند و
  از **۲۰۱۸** به‌روز نمی‌شوند. جست‌وجوی اسکیما اول همین‌ها را می‌آورد.
- بدون فیلتر `Sales.Foroshandeh.ccNoeForoshandeh = 1` (درخواست‌گیر)، سرپرست و
  رییس مرکز با نمره‌های سه‌رقمی صدر جدول را می‌گیرند.

## ایمپورت

در بخش Skills، «افزودن از URL» و آدرس این پوشه در گیت‌هاب:

```
https://github.com/<owner>/<repo>/tree/main/pegah-sales-evaluation
```

کل پوشه با هم می‌آید. چون اسکریپت اجرایی دارد، اسکیل **خاموش** ایمپورت می‌شود؛
بعد از اینکه یک نفر `scripts/score.py` را خواند، روشنش کنید. تغییرات این فایل‌ها
تا ایمپورت دوباره به محصول نمی‌رسد.

## اجرای مستقیم

```bash
python scripts/score.py examples/sample-input.json --period cumulative
python scripts/score.py examples/sample-input.json --period daily --summary
python scripts/score.py - --period daily --json < metrics.json
```

پایتون ۳.۹ به بالا، بدون هیچ وابستگی بیرونی.

## تغییر قاعده‌ها

همه عددهای ارزیابی در `rules.json` است — مبنا، گام، نمره هر گام، ضریب نوع مشتری،
و خط حذف مرجوعی. برای تغییر آستانه، اسکریپت را دست نزنید. `version` را هم عوض
کنید تا معلوم باشد گزارش‌های قدیمی با کدام قاعده درآمده‌اند.

## تصمیم‌هایی که در قاعده‌ها کدگذاری شده

- نمره‌دهی **پیوسته** است: ویزیت مثبت ۴۳.۴٪ با مبنای ۴۰٪ و ۰.۵ نمره در هر ۱٪
  می‌شود ۱.۷ نمره. برای حالت پله‌ای، `"stepping": "stepped"` در `rules.json`.
- معیار ۶ **میانگین** نمره گروه‌های محصول است، نه جمعشان.
- مرجوعی بالای ۲٪ در ارزیابی «تا روز» نمره کل را صفر می‌کند و آن فروشنده ته
  جدول می‌نشیند. نمره خام در `--json` با کلید `raw_total` می‌ماند.

## آنچه هنوز باید با مدیر فروش پگاه چک شود

- **معیار ۴ ارزیابی روز** در برگه اصلی قاعده نداشت؛ قاعده ماهانه (۸۰٪، هر ۱٪
  معادل ۰.۵ نمره) جایش گذاشته شده و در گزارش پاورقی می‌گیرد.
- **کد ۳۵۳ «شبه عمده»** ضریبی نمی‌گیرد. همین‌طور ۳۴۹ تعاونی ویژه، ۳۵۱ و ۳۵۲
  نماینده، ۶۰۷ تعاونی کارکنان.
- **هدف روزانه** از تقسیم هدف ماهانه بر روزهای کاری درمی‌آید.
