# pegah-sales-evaluation

اسکیل ارزیابی فروشنده پگاه، در فرمت استاندارد `SKILL.md`. مستقل است: این پوشه را
هرجا بگذاری کار می‌کند، و برای بردنش به پروژه پگاه فقط همین پوشه لازم است.

```
SKILL.md                      دستورالعمل — چیزی که مدل هر بار می‌خواند
rules.json                    آستانه‌ها، گام‌ها و ضریب‌ها (داده، نه کد)
scripts/score.py              نمره‌دهی
references/metrics.md         تعریف شش متریک و بیرون کشیدنشان از سیستم پخش
references/reporting.md       شکل گزارش
examples/sample-input.json    نمونه ورودی کامل
```

## ایمپورت

در بخش Skills، «افزودن از URL» و آدرس این پوشه در گیت‌هاب:

```
https://github.com/<owner>/<repo>/tree/main/skills/pegah-sales-evaluation
```

کل پوشه با هم می‌آید. چون اسکریپت اجرایی دارد، اسکیل **خاموش** ایمپورت می‌شود؛
بعد از اینکه یک نفر `scripts/score.py` را خواند، روشنش کنید.

## اجرای مستقیم

```bash
python scripts/score.py examples/sample-input.json --period cumulative
python scripts/score.py examples/sample-input.json --period daily --summary
python scripts/score.py - --period daily --json < metrics.json
```

پایتون ۳.۹ به بالا، بدون هیچ وابستگی بیرونی.

## تغییر قاعده‌ها

همه عددهای ارزیابی در `rules.json` است — مبنا، گام، نمره هر گام، ضریب نوع مشتری،
و خط حذف مرجوعی. برای تغییر آستانه، اسکریپت را دست نزنید. `version` را هم عوض
کنید تا معلوم باشد گزارش‌های قدیمی با کدام قاعده درآمده‌اند.

## دو فرضی که در برگه اصلی نبود

- **معیار ۴ ارزیابی روز** (درصد مشتری خرید کرده در روز) در برگه خالی بود؛ اینجا
  همان قاعده ماهانه گذاشته شده: مبنای ۸۰٪، هر ۱٪ معادل ۰.۵ نمره. در `rules.json`
  با کلید `assumed` علامت خورده و در گزارش پاورقی می‌گیرد.
- **«تعداد مغازه»** به‌معنی مشتریانی گرفته شده که در آن بازه فاکتور خورده‌اند،
  نه هر مغازه‌ای که ویزیت شده.

هر دو باید یک بار با مدیر فروش پگاه تأیید شود.

## تصمیم‌هایی که در قاعده‌ها کدگذاری شده

- نمره‌دهی **پیوسته** است: ویزیت مثبت ۴۳.۴٪ با مبنای ۴۰٪ و ۰.۵ نمره در هر ۱٪
  می‌شود ۱.۷ نمره. برای حالت پله‌ای، `"stepping": "stepped"` در `rules.json`.
- معیار ۶ **میانگین** نمره گروه‌های محصول است، نه جمعشان.
- مرجوعی بالای ۲٪ در ارزیابی «تا روز» نمره کل را صفر می‌کند و آن فروشنده ته
  جدول می‌نشیند. نمره خام قبل از صفر شدن در خروجی `--json` با کلید `raw_total`
  می‌ماند.
